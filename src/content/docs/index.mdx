## How the tools use each other

<DogfoodGraph lang="en" />

Each tool was also run on the other repositories, and what got in the way was fixed in the tool itself: [how the tools fixed each other](/dogfooding/).

<ToolSection lang="en" section="cli">
Every version, description, and install command below is read from the npm registry, not typed by hand.
</ToolSection>

<ToolSection lang="en" section="gems">
Every version, description, and install command below is read from RubyGems.
</ToolSection>

<ToolSection lang="en" section="skills">
These have no package registry.
Each description, version, license, and skill name below is read from the repository's own manifest, skill files, README, and LICENSE at the latest commit of its default branch, and each install command is checked against its README.
Each page says which agents the repository supports.
</ToolSection>

<ToolSection lang="en" section="mods">
Each of these is a Claude Code plugin, which its README calls a Claude Mod, that draws a pane beside the transcript.
They work only in Claude Code, and each one needs `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`.
Their facts are read from each repository in the same way as for the plugins and skills above.
</ToolSection>

## Sentences that run

Some sentences on the tool pages carry a small mark such as "checked with archstrict".
That sentence is tied to a command in this repository.
Before each deploy, `npm run claims` runs the command and compares its exit code and output with what the sentence says.
If the tool changes and the sentence stops being true, the check fails and names the sentence.
