## ツール間の依存関係

<DogfoodGraph lang="ja" />

各ツールを他のリポジトリでも動かし、つまずいた点はそのツールの側で直しました。

</ToolSection>

<ToolSection lang="ja" section="gems">

<ToolSection lang="ja" section="skills">
これらにはパッケージレジストリがありません。
以下のバージョン、ライセンス、スキル名は、各リポジトリのデフォルトブランチの最新コミットにあるマニフェスト、スキルファイル、README、LICENSE から読み込んでいます。
インストールコマンドは、README の記載と照合しています。
対応するエージェントは、各ツールのページに書いてあります。
</ToolSection>

<ToolSection lang="ja" section="mods">
いずれも、トランスクリプトの横にペインを表示する Claude Code のプラグインです。
README では、これを Claude Mod と呼んでいます。
Claude Code でしか動作せず、どれも `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` が必要です。
情報は、上のプラグインとスキルと同じ方法で各リポジトリから読み込んでいます。
</ToolSection>

## コマンドで確かめる文

ツールのページには、「archstrict で確認済み」のような小さな印が付いた文があります。
その文は、このリポジトリにあるコマンドと結び付いています。
デプロイのたびに、`npm run claims` がそのコマンドを実行し、終了コードと出力を文の内容と照合します。
ツールが変わって文が正しくなくなると、この検査が失敗し、その文を示します。
