autospawn は、標準入力と標準出力で通信するプログラムのためのランチャーで、既存のプロセスがあれば接続し、なければ起動します。
クライアントは `autospawn connect` を実行します。
その名前の常駐プロセスがすでに動いていれば、connect はそれに接続します。
動いていなければ常駐プロセスを 1 つ起動し、後続のクライアントはすべてそれを共有します。
常駐プロセスは、1Password CLI の `op run` など、自分で選んだコマンドを通して 1 度だけ起動します。
その後は、接続のたびに対象のプログラムを新しい子プロセスとして起動します。
autospawn はバイトを中継するだけで中身を読まないので、MCP サーバーにも、コマンドラインツールにも、長く動く監視プロセスにも使えます。

README が挙げる用途は、シークレットを必要とする MCP サーバーです。
1Password は CLI からのアクセスをターミナルのセッションごとに承認し、MCP クライアントはサーバーを新しいプロセスとして起動します。
そのため起動のたびに承認を求められ、承認の回数はクライアントの数だけ増えます。
autospawn を使うと `op run` は常駐プロセスのために 1 度だけ動き、承認も 1 度で済みます。

## 特徴

- **接続か起動か。**
  `autospawn connect --name <name> -- <command...>` は、`<name>` という名前の常駐プロセスに接続するか、`<command...>` からそれを起動します。
  `--timeout` (既定は 120 秒) は新しい常駐プロセスの起動を待つ時間の上限で、1Password の承認に応じる時間を確保できます。
- **接続ごとに新しい子プロセス。**
  `autospawn serve -- <command...>` は、接続のたびにプログラムを起動します。
  子プロセスの環境変数は、常駐プロセスが起動時に 1 度だけ受け取ったものから、autospawn 自身の `AUTOSPAWN_*` 変数を除いたものです。
  `--idle-timeout` を付けると、子プロセスがない状態がその秒数続いたときに常駐プロセスが終了します。
- **プログラムの終了コード。**
  connect は、プログラムの終了コードで終了します。
  シグナルで終わったときは 128 にシグナル番号を足した値、起動できなかったときは 127 です。
- **接続ごとの値。**
  `connect --param key=value` は 1 つの接続だけに値を送り、`serve --param key=ENV_NAME` はそのキーと、その値を設定する子プロセスの環境変数を宣言します。
  `serve --arg key=v1,v2` は、コマンド中の `{key}` について、接続ごとに選べる値を宣言します。
- **再起動ではなくフィンガープリント。**
  同じ `--name` で別のコマンドを指定した 2 回目の connect は、`fingerprint_mismatch` を受け取って終了コード 1 で終了します。
  常駐プロセスを止めるのは `autospawn stop --name <name>` です。
- **1 つの非公開ディレクトリ。**
  名前ごとのソケット、ログ、起動ロックは `$AUTOSPAWN_DIR` か `$HOME/.local/state/autospawn` の下に置き、ディレクトリはモード 0700 で作ります。
  権限がゆるいディレクトリや、所有者が違うディレクトリは拒否します。

## エージェントでの使い方

Claude Code、Codex、Cursor のような MCP クライアントは、サーバーを直接ではなく autospawn を通して起動します。

```sh
autospawn connect --name example -- op run -- autospawn serve -- node /path/to/server.js
```

最初に `example` を起動したクライアントが 1Password の承認を 1 度求め、その後は、どのクライアントから起動しても常駐プロセスに接続します。

トークンが必要なツールをタスクごとに 1 回実行するエージェントも、同じ形を使います。

```sh
autospawn connect --name example-cli -- \
  op run -- \
  autospawn serve --idle-timeout 3600 -- \
  example-tool fetch
```

ツールの出力は標準出力に届き、connect はツールの終了コードで終了します。
エージェントから見ると、`example-tool fetch` を直接実行したときと同じです。
1Password の項目や、プログラムが依存するほかのものを変更したら、`autospawn stop --name example` を実行します。
すると、次の connect が新しい常駐プロセスを起動します。

## はじめかた

autospawn には Node.js 24.10 以降が必要で、macOS と Linux で動きます。
Unix ドメインソケットで通信するので、Windows では動きません。

```sh
npm install -g autospawn
```

1Password の例について、`mcp.json`、`claude mcp add-json`、`~/.codex/config.toml` の設定の全文は README にあります。
