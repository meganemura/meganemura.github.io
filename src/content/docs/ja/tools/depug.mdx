depug は、TypeScript のテスト失敗を、コーディングエージェントが読める証拠に変えます。
失敗したテストを調べるエージェントは、ふつう周りのコードから値が何だったかを推測します。
depug はテストを計装して再実行し、値が実際に何だったかを報告します。
vitest と Node 自身のテストランナーで動きます。

## 特徴

- **失敗時の証拠。**
  レポーターを入れると、失敗したテストは、JSON ファイルを示す `depug evidence:` の行と、そのテストだけを再実行するコマンドを示す `depug rerun:` の行を表示します。
  誤った値を作ったコードがまだスタックにあるかどうかも、注記で示します。
- **`probe`。**
  1 つの関数へのすべての呼び出しを、引数と戻り値つきで一覧します。
  観測した形を宣言された型と並べ、`mismatch: id was string, declared number (5 of 5 calls)` のように示します。
- **`flt`。**
  1 回の呼び出しを行ごとに追い、どのローカル変数がどの行で変わったかを示します。
- **`frames` と `preflight`。**
  `frames` はテストが呼んだ関数を一覧し、`--at <file:line>` でソースの行を関数の ID に変えます。
  `preflight` は、呼び出しの番号が 2 回の実行で同じままかを確かめます。
- **`exec`。**
  1 つの行で、その関数自身のスコープで式を実行し、実行の結果を報告します。
- **`rerun`。**
  テストのコマンドを時間制限つきで実行し、既定では 120 秒で止めます。
  終わらないテストは、テストランナー自身のタイムアウトが頼るワーカーを止めてしまうからです。

関数の ID は `path:name@line:column#k` の形で、`k` は 1 つのテストの中でのその関数の呼び出しを数えます。

## エージェントでの使い方

1. 失敗したテストが、証拠のパスと再実行のコマンドを表示します。
2. 失敗した呼び出しが記録されたフレームにあると注記が言えば、エージェントは証拠のファイルを読みます。
3. そうでなければ、表示されたコマンドの前に動詞を付けます。
   `depug preflight` を実行し、次に怪しい関数に `depug probe` を、最後に誤った呼び出しに `depug flt` を実行します。

README の実例では、この流れで IPv6 の処理の切り捨てのバグを、3 つのコマンドと約 4 秒で見つけました。
値を推測するために実装を読む手順はありませんでした。
depug は動詞を実行したときだけプロセスを起動するので、成功するテストスイートには負担がありません。
パッケージには、出力の読み方をエージェントに教えるスキルが入っています。

## はじめかた

```sh
npm install --save-dev @meganemura/depug
```

vitest の設定にレポーターを加えます。
動詞には設定がいりません。

```ts
import { defineConfig } from "vitest/config";
import DepugReporter from "@meganemura/depug/reporter";

export default defineConfig({
  test: {
    reporters: ["default", new DepugReporter()],
  },
});
```

```sh
npx depug probe "src/utils/ipaddr.ts:expandIPv6@13:14" -- npx vitest run "src/utils/ipaddr.test.ts" -t "^expandIPv6 Should result be valid$"
```
