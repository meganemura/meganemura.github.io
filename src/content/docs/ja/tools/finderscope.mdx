finderscope は、V8 のプロファイル (`.cpuprofile`、`.heapprofile`、`.heapsnapshot`) を、コーディングエージェントが一度で読める短い順位付きの報告に変えます。
報告の最後の `do:` の行が、次に実行するコマンドを示します。
要約は、エージェントが編集できる関数を、その関数が引き起こしたコストで順位付けます。
各サンプルは自分のコードのうち最も深い関数に属するので、依存パッケージの中で使った時間は、それを呼んだ自分のコードの分になります。

## 特徴

- **コマンドのプロファイル。**
  `finderscope run -- <command>` はコマンドをプロファイルし、プロファイルと子プロセスの出力を作業用のディレクトリに残します。
  報告全体は `report.txt` に、`--json` なら `report.json` に書き出します。
- **自分のコードが先。**
  `own` は、エージェントが編集できる本物のソースを指します。
  各行は、関数の自己時間と、パッケージなどほかの領域への呼び出しのうち大きい 3 つを示します。
- **掘り下げるコマンド。**
  `top`、`callers`、`callees`、`lines` は、報告に表示されたとおりの関数のキーか、1 つの関数にだけ一致する名前を受け取ります。
  見つからないときは、近いキーを使う実行可能なコマンドを 3 つまで表示します。
- **時間の窓。**
  `timeline` は CPU プロファイルを 20 の等しい区間に分け、`--from` と `--to` はどの報告も 1 つの窓に絞ります。
- **メモリ。**
  `run --heap` はヒープのプロファイルを記録し、`run --heap-snapshot` は `heapUsed` がより高い山に達するたびにスナップショットを書きます。
  `retainers <snapshot> <constructor-or-#id>` は、あるオブジェクトを保持しているものを示します。
- **比較と JSON。**
  `finderscope diff <before> <after>` は 2 つのプロファイルを比べます。
  `--json` の報告には、CPU プロファイルなら `"us"`、ヒーププロファイルなら `"bytes"` の `unit` が最上位に付きます。

## エージェントでの使い方

パッケージには、短いプロファイリングの手順を示すスキルが入っています。

1. `finderscope run -- <command>` を実行します。
2. 修正候補と最後の `do:` の行を読みます。
3. `finderscope lines` などの `do:` のコマンドを実行し、`callers` や `callees` でコストをたどります。
4. 変更の後、`finderscope diff` で変更前と変更後のプロファイルを比べます。

`do:` のコマンドの引数はすべて単一引用符で囲まれるので、パスに何が含まれていても `sh -c` でそのまま動きます。

## はじめかた

```sh
npm install --save-dev finderscope
npx finderscope run -- node app.js
```
