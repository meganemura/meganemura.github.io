headsign は、コーディングエージェントがプロジェクトの作業の進め方を作り、改善するための 2 つのスキルです。
エージェントには、求める結果、制約、プロジェクトで実行できるチェックを渡します。
方法はエージェントが選び、そのチェックを使い、フィードバックで弱点が見えたら方法を改善します。
どちらもホスト自身のツールとプロジェクトのコマンドを使う普通のスキルで、headsign の CLI、ワークフローの状態、フック、npm でのインストール、ビルドの手順は必要ありません。
README には、Codex と Claude Code 向けのインストールコマンドが載っています。

## 特徴

- **`create-project-skill`。**
  リポジトリの証拠や、渡されたコマンドから、プロジェクト専用のスキルを作ります。
- **`improve-project-skill`。**
  既存のプロジェクト専用のスキルを、作業のフィードバックと証拠から改善します。
- **作業中の修正。**
  レビューの指摘が繰り返されると、エージェントは自分の方法がなぜそれを見逃したかを調べ、方法を直し、その修正を適用してから再提出します。
- **守られる範囲。**
  改善はタスクの権限と残りの予算の中に収まります。
  エージェントは明示された制約を守り、止める指示に従い、頼まれた範囲を超える作業には権限を求めます。
- **証拠としてのチェック。**
  チェックは証拠を提供しますが、その証拠が求められた結果を満たしているかどうかは、引き続きモデルが判断します。
  テストが通っても、すべての要件を満たしていることの証明にはなりません。

## エージェントでの使い方

たとえば次のように、スキルを名前で指定してエージェントに頼みます。

> Use create-project-skill to create a local skill for this repository.
> Discover the checks it can run. Preserve our required outcomes and constraints.

スキルを作ることと、そのスキルが説明する作業をすることは、別のタスクです。
両方を任せるには、"Then use the new skill to complete the task we agreed on." と書き添えます。
これらのスキルをインストールしても、古い headsign プラグインのフックは止まりません。
v0.16.0 以前からの更新については、README が移行の手引きを案内しています。

## はじめかた

インストーラーはどちらでも使えます。
次のコマンドは、両方のスキルを Codex のユーザースコープにインストールします。

```sh
gh skill install meganemura/headsign --all --agent codex --scope user
npx skills add meganemura/headsign --skill '*' --agent codex --global
```

Claude Code では `codex` を `claude-code` に置き換えます。
`gh skill` は最新の GitHub Release を、`npx skills` はデフォルトブランチを使います。
