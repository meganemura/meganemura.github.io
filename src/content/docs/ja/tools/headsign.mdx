headsign は、コーディングエージェントがプロジェクトの仕事の進め方を作り、改善するための 2 つのスキルです。
エージェントには、求める結果、制約、プロジェクトで実行できるチェックを渡します。
方法はエージェントが選び、そのチェックを使い、フィードバックで弱点が見えたら方法を改善します。
どちらもホストの道具とプロジェクトのコマンドを使う普通のスキルで、headsign の CLI、ワークフローの状態、フック、npm のインストール、ビルドの手順はいりません。
README には、Codex と Claude Code へのインストールのコマンドがあります。

## 特徴

- **`create-project-skill`。**
  リポジトリの証拠や、渡されたコマンドから、ローカルなスキルを作ります。
- **`improve-project-skill`。**
  既存のローカルなスキルを、作業のフィードバックと証拠から改善します。
- **作業中の修正。**
  レビューの指摘が繰り返されると、エージェントは自分の方法がなぜそれを見逃したかを調べ、方法を直し、その修正を当ててから出し直します。
- **守られる範囲。**
  改善はタスクの権限と残りの予算の中に収まります。
  エージェントは明示された制約を守り、止める指示に従い、頼まれた範囲を超える作業には権限を求めます。
- **証拠としてのチェック。**
  チェックは証拠を出しますが、その証拠が求めた結果に届いているかはモデルが判断します。
  テストが通っても、すべての要件を満たしたことにはなりません。

## エージェントでの使い方

スキルを名前で指定して、エージェントに頼みます。

> Use create-project-skill to create a local skill for this repository.
> Discover the checks it can run. Preserve our required outcomes and constraints.

スキルを作ることと、そのスキルが説明する作業をすることは、別のタスクです。
両方を許すには、"Then use the new skill to complete the task we agreed on." を加えます。
これらのスキルを入れても、古い headsign プラグインのフックは止まりません。
v0.16.0 以前からの更新については、README が移行の手引きを案内しています。

## はじめかた

インストーラーはどちらでも使えます。
次のコマンドは、両方のスキルを Codex のユーザー範囲にインストールします。

```sh
gh skill install meganemura/headsign --all --agent codex --scope user
npx skills add meganemura/headsign --skill '*' --agent codex --global
```

Claude Code では `codex` を `claude-code` に置き換えます。
`gh skill` は最新の GitHub Release を、`npx skills` は既定のブランチを使います。
