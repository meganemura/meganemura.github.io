nukadoko は、型付きのステップ契約のもとで Gherkin のシナリオを実行し、実行のたびにステップ記録を書き出します。
実装は今や生成されるものになり、それを検査する基準は固定されていなければなりません。
受け入れ基準は、それを決めた人たちの言葉で書かれたままにします。
その文とテスト対象のシステムの間にあるものは、すべて型付きで、実行前に検査され、差分でレビューできます。
ステップ記録はツール自身が測定するので、実行についてのエージェントの説明を信じる必要はありません。
どの実行も Markdown の実行サマリーで終わり、その実行が証拠になります。
つまり、これらのシナリオがこのコミットで、この条件のもとで動いた、という証拠です。
人は `.feature` とそのサマリーを読み、承認をどこに記録するかは nukadoko の外で決めます。

## 特徴

- **実行前にわかる誤り。**
  `nuka check` は、すべてのフィーチャーファイルとステップファイルを読み、未定義のステップ、重複したパターン、あいまいなステップ、順序が誤っている `from` のバインディング、コードを実行するステップに結び付いた Then、プロジェクトにインストールされていない Playwright を必要とするステップなどを報告します。
  `nuka check --codes` は、すべての指摘コードを一覧表示します。
  `nuka run` も実行の前に同じ検査を行い、エラーがあれば止まります。
  `--no-check` を付けると、この検査を省きます。
- **Then はコードではなく主張を宣言する。**
  型付きの Then は、読む値、比べ方、期待する値の出どころを宣言します。
  期待する値は、ステップが別の出どころを指定しない限り、その文から取ります。
  比べるのは nukadoko で、主張が崩れると、`"Hello, Ada!" (from:run-greet@5.stdout as text) equal "Hi, Ada!" (sentence:text)` のように、両方の値とそれぞれの出どころを出力します。
- **ステップ記録。**
  `nuka do` は 1 つのステップを単独で実行し、検証済みの結果を含むステップ記録を出力します。
  `nuka run` はシナリオを実行し、同じ記録を残します。
  ステップが送った HTTP のリクエストは記録の `http.jsonl` に残り、エクスポートされた `runCommand` を呼ぶステップは、起動した各プロセスを `observed.processes` に残します。
- **プログラムは nukadoko が起動する。**
  `nukadoko.program.ts` は、テスト対象のプログラムを `defineProgram` で記述します。
  nukadoko はそれをビルドして準備し、実行ごとに空いているポートで起動し、応答するまで待ち、各ステップのリクエストをそこへ送り、シナリオの後で止めます。
- **証拠としての実行サマリー。**
  どの `nuka run` も `.nukadoko/runs/<run_id>/summary.md` を書き出します。
  そこには、基準と環境ごとの判定の表、すべての主張とその結果を並べた Claims の節、コミット、失敗した各シナリオを再実行するコマンドが並びます。
  `$GITHUB_STEP_SUMMARY` が設定されていれば、そこに追記します。
  `nuka run --base <ref>` を付けると、各基準が基点から見て新しいか、変わったか、変わっていないか、消えたかを示し、新しい基準や変わった基準が基点のコードで失敗したかどうかも示します。
  `nuka report --format markdown|allure|messages` は、終わった実行を、その実行ディレクトリだけから描画します。
  `--out <path>` を渡すと、CI のステップがプルリクエストのコメントとして投稿するサマリーを書き出します。
- **既存のスイートの入口。**
  import を 1 つ `@cucumber/cucumber` から `nukadoko/compat` に替えると、cucumber-js のスイートは動き続け、nukadoko がそのステップを記録し始めます。
  その後、各ステップを個別に `defineStep` へ移せます。

## エージェントでの使い方

エージェントは、人の手を借りずにループ全体を回せます。

1. `nuka steps --json` で語彙を調べます。
2. `nuka describe` で、スキーマを JSON Schema の形にした契約を読みます。
3. `nuka do` で 1 つのステップを実行し、ステップ記録を読んで、次の呼び出しを選びます。
4. 語彙に操作が足りなければ、`nuka scaffold <name> --pattern "<line>"` でステップを追加します。
   フィーチャーを先に書いた場合は、`nuka scaffold --feature <file>` が未定義の行ごとにスタブを 1 つ書き出します。
   `--command <entry point>` は、組み込みの `scratch` のディレクトリでプログラムを実行する When のステップを書き出し、`--request "<METHOD> <path>"` はプログラムの URL を呼ぶ When のステップを書き出します。
   `--then --from <step>.<key>` は、その値を文と比べる主張を持つ Then のステップを書き出します。
5. フィーチャーを書き、そのフィーチャー、複数のファイル、またはディレクトリを対象に `nuka check` を通し、green になるまで `nuka run <feature>` を実行します。
   シナリオが失敗すると、stderr にそのステップ、エラー、ステップ記録、再実行のための `nuka run <feature>:<line>` が出ます。
6. フィーチャーとその実行サマリーを、人のレビューに渡します。

`nuka check` は、毎回の実行の前に通す静的なゲートです。
対象を指定しないときは、壊れてはいないが傷みつつあるものについての注記も加えます。
たとえば、どこでも使われない `from` の宣言、どのフィーチャーにも結び付かないパターン、説明のないスキーマのフィールドです。
注記は終了コードを変えず、`--fail-on <code>` を付けると、指定したコードで終了コードを失敗にできます。
パッケージには 2 つのスキルが含まれています。
`nukadoko` は要求から、シナリオと、その証拠になる実行までを進めて人のレビューに渡します。
`nukadoko-verification` は、プロジェクトの検証スキルの下に、その機能マップを証明する層としてシナリオを置きます。

## はじめかた

nukadoko には、22 系の Node 22.18 以降か、Node 23.6 以降が必要です。
これらは、フラグなしで `.ts` のファイルを実行できるリリースです。
nukadoko は設定とステップファイルを Node 自身の型の除去で読み込むので、独自の TypeScript ローダーをインストールしません。

```sh
npm install -D nukadoko
npx nuka init
npx nuka scaffold run-greet --pattern "I run greet with {name:string}" --command src/cli.ts
```

`nuka init` は、CLI や API のプロジェクトを前提に準備をします。
`nukadoko.config.ts` と `features/steps/` を書き出し、`.gitignore` に `.nukadoko/` を追加し、`tsconfig.json` の `include` にステップと設定を加え、`nuka run` を実行する `test:scenarios` スクリプトを追加します。
以後、人も CI も `npm run test:scenarios` の 1 つだけを実行すれば済みます。
対象を指定しない `nuka run` は、`featuresDir` を検査してから実行します。
scaffold の行は、プログラム `src/cli.ts` を実行してその `exitCode`、`stdout`、`stderr` を返す When のステップを書き出します。
nukadoko はブラウザーをインストールしません。
Playwright は省略可能な peer dependency で、`page` や `request` を使うステップだけが必要とします。
`nuka run` は Allure の結果も cucumber-messages のストリームも書き出しません。
それらは `nuka report` が終わった実行から描画し、`nuka init --allure` は Allure のための `allurerc.mjs` を書き出します。
`gh skill install meganemura/nukadoko --all` で、2 つのスキルをインストールします。
`nuka skill path` は、インストールした版に合うスキルのディレクトリを出力します。
