pstack-portable は、上流の [pstack](https://github.com/cursor/plugins/tree/main/pstack) を Claude Code と Codex で動かします。
ワークフローは上流のものです。
このリポジトリが加えるのは、Cursor の道具を今のホストの道具に置き換える 1 つのラッパーのスキル、`poteto-mode-portable` だけです。
上流で `/poteto-mode` を使う場面で、これを使います。
Cursor は上流の pstack をそのまま動かすのでラッパーは不要で、Cursor 向けのラッパーのマニフェストは未検証です。

## 特徴

- **1 つのマーケットプレイスに 2 つのプラグイン。**
  `pstack-portable` がラッパーで、`pstack` は、ラッパーが対応するコミットに固定した、手を加えていない上流の pstack です。
  ラッパーは `pstack` のファイルを読むので、`pstack` はインストールして無効のままにします。
- **名前で頼むワークフロー。**
  "Use poteto-mode-portable to fix this bug." のような依頼で、上流のワークフローをラッパー経由で動かします。
  スラッシュコマンドは `/pstack-portable:poteto-mode-portable` です。
- **ホストごとのモデルの設定。**
  "Use poteto-mode-portable to configure pstack." は、1 つのプロジェクトなら `.pstack/models/<host>.md` に、すべてのプロジェクトなら `~/.agents/pstack/models/<host>.md` に書きます。
  `<host>` は `claude-code` か `codex` で、プロジェクトのファイルが優先します。
- **確かめるスクリプト。**
  ラッパーは、知らないスクリプトや変わったスクリプトを止め、実行の前にスクリプトの前提条件を確かめます。
- **見える不足。**
  ワークフローがホストにない能力を必要とするとき、ラッパーは代わりの結果ではなく、その不足を報告します。
- **固定できるリリース。**
  リリースごとに `v<version>` のタグがあります。
  Claude Code では `meganemura/pstack-portable#v<version>` で、Codex では `--ref v<version>` でマーケットプレイスを追加します。

## エージェントでの使い方

pstack のワークフローを、ラッパー経由で頼みます。

```text
Use poteto-mode-portable to fix this bug.
Use poteto-mode-portable to interrogate this diff.
Use poteto-mode-portable to tdd this fix.
```

ラッパーが仕事を任せる先は、今のホストのサブエージェントだけです。
ほかのエージェントのアプリケーションやプロバイダーの CLI は起動せず、フック、Cursor Automations、クラウドのワーカー、永続するスケジュールも提供しません。

## はじめかた

Claude Code では `pstack` が無効の状態でインストールされます。

```sh
claude plugin marketplace add meganemura/pstack-portable
claude plugin install pstack-portable@pstack-portable
claude plugin install pstack@pstack-portable
```

Codex では次のコマンドを使います。

```sh
codex plugin marketplace add meganemura/pstack-portable
codex plugin add pstack-portable@pstack-portable
codex plugin add pstack@pstack-portable
```

その後、`~/.codex/config.toml` の `[plugins."pstack@pstack-portable"]` に `enabled = false` を設定します。
